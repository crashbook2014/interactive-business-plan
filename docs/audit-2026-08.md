# Wodouh — production-readiness audit

**1 August 2026.** Every claim below traces to a command that can be re-run.
Where something could not be verified in this environment, it says so rather
than being inferred.

---

## Executive summary

Ten defects found, **ten fixed and deployed**. Three were in the calculations,
which is where this product's real risk lives — including one that overstated a
claim by **18.5×** with nothing on screen to suggest anything was wrong. Two
more were latent rather than live: not reachable when found, and recorded as
not reachable rather than dressed up as a save.

**A large part of the requested audit had no subject** *at the time it was
written.* The application made no network calls of any kind, so AI features,
prompt injection, API security, SQL injection, CSRF, login, sessions, tokens
and server rate limiting were marked N/A with that evidence rather than padded
with invented findings.

> **Superseded in part, August 2026.** The termination assessment added an
> optional Claude document analysis. It is **off in every build that ships** —
> `test/claude-path.test.js` proves zero off-origin requests in that state — so
> the N/A findings still describe what users receive. But **prompt injection
> and API security are now live concerns for any deployment that configures
> it**, and are treated as such in `docs/claude-analysis.md` and in the
> security section below. SQL injection, CSRF, login, sessions and tokens
> remain N/A: there is still no database, no auth and no session.

**Production-readiness score: 75/100** (was 71 — observability moved from 0 to
4 when CI and the live watchdog landed). Arithmetic shown below so it can be
argued with.

## Phase 1 — What this application is

A static, three-page site. No build step, no framework, no bundler, no
dependencies at runtime.

| | |
|---|---|
| `app/index.html` | The entire product: 25 screens, 17 analyzer rules, 24 knowledge entries, 24 library entries, and the full termination assessment |
| `web/index.html` | Landing page |
| `brand/index.html` | Brand specification |
| `index.html` | **Not Wodouh.** A 344 KB business plan for an unrelated project, served at `/` |
| `assets/fonts/` | Two variable fonts, shared by all three pages |
| `supabase/` | Schema, RLS, Edge Functions, auth client, Claude analysis proxy. **Never executed** |
| `test/` | Eight suites plus a runner (`npm test`), a static server, and a live-site watchdog |
| `.github/workflows/` | CI on every push; watchdog every six hours |

**How it works.** A contract is pasted or extracted from a PDF entirely on the
device. 17 regular expressions match clauses. Matched clauses produce a
decision — safe, negotiate, or see a lawyer — a score, and per-clause guidance,
each carrying either a verified article citation or an explicit "Wodouh's
reading" label. State lives in `localStorage`. Nothing leaves the browser —
with one exception, added after this audit: an optional Claude read of the
contract text, off unless configured and then only with per-document consent.
See `docs/claude-analysis.md`.

**Two legal tracks.** Saudi and resident diverge wherever the law does, most
consequentially in the Article 77 compensation formula.

## High priority

### H1 — A year typo silently multiplied a claim by 18.5× · FIXED

| | |
|---|---|
| **Location** | `compEstimate()` / `remainingTermMonths()`, `app/index.html` |
| **Root cause** | The fixed-term Article 77 branch multiplies remaining months by wage with no plausibility bound. A contract end date of 2099 instead of 2029 is a single-character typo |
| **Measured** | 480,000 SAR became **8,880,000 SAR**. No warning, in the surface the register itself calls highest-risk |
| **Severity** | **High** — silent, plausible, and about money |
| **Fix** | Flag a remaining term over 60 months and ask the reader to check the year. **Deliberately not capped** — capping would invent a number for someone with a genuinely long term |

```js
const TERM_SANITY_MONTHS = 60;
function termLooksImplausible(){
  const m = remainingTermMonths();
  return m != null && m > TERM_SANITY_MONTHS;
}
```

Verified: warning fires at 74 years, silent at 4.

## Medium priority

### M1 — A negative day component reached the money · FIXED

| | |
|---|---|
| **Location** | `serviceParts()` |
| **Root cause** | From 31 Jan to 1 Mar the single borrow is a 29-day February against a 30-day shortfall, leaving `d = -1`, which then subtracts through `serviceYears` |
| **Measured** | 402.97 SAR where 416.67 was owed — a **3.3% understatement**, on 1 in 42 month-end starts |
| **Fix** | Floor the day component at zero after the borrow; the span is a completed month with no extra days |

Verified: 0/42 month-end starts negative after.

### M2 — Duplicated module that could silently drift · FIXED

`app/js/wodouh-calendar.js` duplicated calendar logic that was deliberately
inlined into `app/index.html`. Two copies, one shipping, one not. Deleted;
export still produces 3 events and a 1,454-byte `.ics`, which also proves the
deleted copy was dead. `wodouh-auth.js` moved to `supabase/client/` — not dead,
but unwired, and the folder structure should say so.

### M3 — Touch targets below the WCAG minimum · FIXED

Language toggle 36px, three add-to-letter buttons 40px, against a 44px
minimum (WCAG 2.5.5), on a mobile-first app. Raised via `min-height` so only
the tappable area grew.

## Low priority

### L1 — Heading order jumped h2 → h4 · FIXED
WCAG 1.3.1. A screen-reader-only `h3` fixes the hierarchy without renumbering
five CSS selectors and every flag template.

### L2 — `NaN` passed the end-of-service guard · FIXED
`y <= 0` is false for `NaN`, so an unparseable date reached the arithmetic and
the reader saw "not a number" where a figure belonged. Now `!(y > 0)`. Not
reachable through a conformant date input — defence in depth.

### L3 — Two fixed limits that the code around them had outgrown · FIXED

Found by the surface sweep, and worth recording together because they are the
same defect twice: **a number that was in range when it was written, with
nothing holding it there.**

| | |
|---|---|
| **Location** | `AR_NUM` / `buildLetter()` and `answerRisks()`; `pwPlan` / `renderPaywall()` |
| **Root cause** | A nine-slot table of Arabic-Indic numerals numbered a list with no upper bound. Separately, one selected-plan index is shared by two plan lists of different lengths — three for the letter, two for the case file |
| **Consequence** | The Arabic letter prints `undefined.` where a point number belongs — in the paid document. The pay button reads "Pay undefined" |
| **Reachable** | **No, and stated as no.** The ceiling on numbered points is **7** on the Saudi track, 6 on resident, measured not assumed. Every paywall entry point resets the index today |
| **Why fix it anyway** | The rule set went from 10 to 17 rules in this session and the ceiling moved with it. Two more rules and the first one ships |
| **Fix** | Convert the digits rather than look them up — conversion is total. Clamp the plan index in the render, so it is a property of the paywall rather than of every caller remembering |

```js
function pointNum(i){
  const n = String(i + 1);
  return lang === "ar" ? n.replace(/[0-9]/g, d => "٠١٢٣٤٥٦٧٨٩"[+d]) : n;
}
pwPlan = Math.max(0, Math.min(pwPlan, activePlans().length - 1));
```

Verified: a 40-point letter numbers cleanly in both languages; the pay button
never reads "undefined" across a mode switch.

### L4 — Root of the domain is unaudited third-party content · OPEN
`index.html` at `/` is an unrelated 344 KB business plan with its own scripts.
Not Wodouh, but same origin and same domain reputation. **Left alone
deliberately — it is your content and not mine to remove.**

## Bugs found · broken buttons · incorrect calculations

**Broken buttons: none.** All 19 interactive controls on the result screen
have accessible names and working handlers. Every back path across 18 screens
resolves correctly. All five library CTAs navigate.

**The eight screens no suite had touched** are now covered by
`test/surfaces.test.js` — 60 assertions, all passing:

| Surface | What was asserted |
|---|---|
| Letter builder | Selection renumbers from 1 rather than carrying the clause index; deselected points are absent; 40 points number cleanly in both languages |
| Paywall | Exactly one plan selected; the pay button price follows the selection; **withheld points never enter the DOM before payment** |
| Triage | All six reason × notice × probation combinations reach the right verdict; the case-file route appears only when there is a claim; an unanswered question renders no verdict at all |
| Case file | Meter reads 0% and 100% at the ends; un-ticking removes exactly one; leave days clamp at 0 and 365 and survive non-numeric input |
| Business tier | Three plan cards; monthly/yearly changes the prices; no `undefined` or `NaN` anywhere in the workspace |
| Photo intake | The shutter reveals the honest "not yet" note rather than pretending to read |
| Unreadable path | Every string populated, three tips, retry returns home with the box cleared. `legible()` rejects empty, short and gibberish input and accepts a real contract |
| Clause list | Every clause listed, no `undefined` or `NaN` |

**Incorrect calculations: two, both fixed** — H1 and M1 above.

Everything else passed property-based fuzzing: `serviceParts`,
`resignFactor`, `calcEos`, `compEstimate`, `remainingTermMonths`,
`leaveAmount`, `claimTotal`, `decide`, `confidence`, `scoreBand`, `money`,
`fmtNum` — across boundaries (exactly 2/5/10 years), reversed dates, zero and
negative wages, empty and non-numeric input, `MAX_SAFE_INTEGER`, and dates from
1899 to 2100. Invariants asserted rather than expected constants: the award is
never negative, never decreases as service grows, and the Article 77 floor
always holds.

## Security

**Verified clean:** no committed secrets (repo-wide scan). No XSS vector —
`analyzePasted` sets `q:null`, so contract text never reaches `innerHTML`; user
input reaches the DOM only via `.value` and `textContent`. CSP, `nosniff` and
a strict referrer policy ship on all three pages. `localStorage` is validated
and clamped on read, and a tampered payload resets rather than rendering
partial state.

**N/A with evidence:** SQL injection, CSRF, authentication, authorization,
tokens, sessions — still no database, no auth, no session.

**No longer N/A, for any deployment that configures the optional Claude read:**

| Concern | Treatment |
|---|---|
| **Prompt injection** | A contract is attacker-controlled text. The document is passed as delimited data the model is told to distrust, never concatenated into the instruction; the response shape is constrained so a hijacked completion fails parsing; and every field reaches the DOM through `textContent`. The test injects `<img src=x onerror=...>` and asserts it renders as visible text. **What none of this prevents** is a model persuaded to describe the contract inaccurately in prose — which is why the panel is labelled Wodouh's reading, sits below the verified sources, and feeds into no amount |
| **API security** | The Anthropic key lives only in Edge Function secrets. Requests capped at 40 KB, rate limited to 10 per caller per minute, upstream error bodies never relayed |
| **Server rate limiting** | Present on the analyze function; keyed on a hash of the caller address, not the address |
| **The privacy promise** | Verified to track the build: unconditional when nothing is configured, stating the exception when something is |

**Known and accepted:**

| Item | Status |
|---|---|
| `script-src 'unsafe-inline'` | Required — one inline script, 50 `onclick` attributes. Removing it is a refactor with more regression risk than it buys |
| `frame-ancestors`, HSTS | Cannot be set. GitHub Pages does not serve custom headers |
| Redemption codes | **Not secure and documented as such.** Browser-side checks are bypassable. Sized for tens of buyers, not launch |

## Performance

Measured, not estimated:

| | Before | Now |
|---|---|---|
| App page | 426 KB | **249 KB** (gz 207 → 71) |
| Landing | 226 KB | **49 KB** (gz 151 → 15) |
| Brand | 208 KB | **31 KB** (gz 145 → 9) |
| First contentful paint | — | **80 ms** app, 180 ms landing |
| Requests | — | **3** (page + 2 fonts) |

CSS coverage over a broad session: **52.6% used, 34 KB unused** across 18
screens — expected rather than a defect, since one session cannot visit every
screen.

**JS coverage is not reported.** V8 treats the whole inline script block as a
single range and returns 100%, which would falsely imply no dead JavaScript. A
wrong measurement is worse than none.

**Memory:** the one real leak — the boot sequence swallowed into `toggleLang()`
by a missing brace, duplicating tracked reminders 1→5 over four language
toggles and re-binding every listener — was found and fixed earlier this
session. `initIntake` and `initGestures` are now idempotent.

## UX

Fixed during this audit: touch targets, heading order. Fixed earlier: the score
ring contradicting the decision, five competing next-steps, two stacked
segmented controls, onboarding gating the front door.

**Outstanding, needs a real user rather than my judgment:**

- **Hijri dates.** The calculator is Gregorian-only. Saudi contracts routinely
  state Hijri dates and end-of-service turns on exact dates. I do not know
  which people reach for, and guessing is how you get this wrong.
- **Arabic phrasing coverage.** The routing audit found possessive forms
  failing routinely — `إجازتي` did not match `إجازة`. Fixed for the cases I
  could imagine. Real questions will break it in ways I cannot invent.

Payments remains a deliberate zero. Observability was the other, and is now

is left open because closing it means the app phoning home, which is a product
decision about the privacy promise rather than a default.

**This score predates the termination assessment** and has not been recomputed
for it. That feature ships with 61 of its own assertions plus the Claude-path
suite, but it has not had an independent audit pass of the kind the rest of
this document records — and it is the highest-stakes surface in the product,
because it puts riyal figures in front of someone who has just lost their
income. Treat 71/100 as describing what was audited, not everything that now
ships.

## What could not be verified here

- **Real browsers.** All testing was headless Chromium on Linux. No Safari,
  iOS, Firefox or Android device.
- **Screen readers.** None available. Programmatic checks pass; that is
  necessary, not sufficient.
- **The backend.** `supabase/` has never executed. No migration applied, no
  login completed, no webhook received.
- **Zid and Salla endpoints.** Unreachable from this environment; the adapter
  URLs come from documentation, not testing.
- **Legal accuracy.** 24 claims verified against official sources and firm
  commentary by me. **No lawyer has reviewed any of them.**
